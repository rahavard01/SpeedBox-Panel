# WatTunnel in SpeedBox

The fourth tunnel engine has an independent schema and form. It forwards TCP,
UDP or both, with ICMP (IPv4), UDP, TCP, TLS, WS, WSS, H2, H2C and gRPC carriers.
All except UDP support reverse dialing. Iran always owns the public user ports;
the foreign process forwards only to explicitly allowed localhost target ports.
IPv6 is available for the eight non-ICMP carriers. Sessions greater than one
are accepted only for a normal, non-ICMP carrier.

Creation requires a completed, fresh measurement bound to the two registered
servers, carrier, direction, address family and usable TCP/UDP protocols.
Test direction and carrier selection are independent of the existing engines.
Temporary tests use bounded systemd units, loopback echo targets, both-host
cleanup, cancellation and shared server leases. They never change firewall,
routes or sysctls. Open the intended transport/ICMP path in the host/provider
firewall as appropriate. Temporary port tests do not guarantee a production port
is permitted by the provider or reachable by all users.

The form exposes carrier-specific pool/ICMP/TLS/HTTP controls, MTU, FEC, pacing
(MB/s, not Mbps), sessions, keepalive, UDP idle timeout, monitoring, scheduled
restart and Telegram outage alerts. Bonding, fake-SNI packet injection, ECH
bootstrap and third-party CDN management are not exposed by this integration.
Operations include connection status, start/stop/restart, logs, edit, delete,
and inspection/update to the compatible bundle supplied with the panel.

## Engine supply and security

Integration version `2.10.9-sb1` is built from upstream commit
`7c30c59a65f962ceb6763daf23952ecbc5e7de91` with patched Go 1.26.10. It replaces
the upstream 4096-byte UDP reply read with full datagram buffers borrowed only
after a socket becomes readable. Idle flows do not each retain 64 KiB.
The engine's fragmentation/MTU limits still apply, especially with small ICMP
MTUs. Linux amd64 and arm64 bundles and compressed/uncompressed SHA-256 hashes
are shipped in `wattunnel-dist`; no compiler is needed on panel or tunnel hosts.

`scripts/wattunnel/build.py` reproduces the bundle from the immutable upstream
commit and recorded overlay. `scripts/verify-wattunnel.py` verifies the recorded
integration sources and both binary archives. The panel uploads and verifies
the hashes through its existing direct SSH connection. It does not execute the
upstream installer/manager, bootstrap proxies, global tuning or automatic updates.

Credentials are generated by the panel, encrypted in the database, hidden from
API responses and kept in mode-0600 files. Engine command lines contain the
credential file path. Each instance has an explicit TCP/UDP target allowlist
and reserved transport/metrics ports. Metrics bind only to 127.0.0.1 and are read
over SSH; they are never exposed as a public control endpoint. A service gets
only CAP_NET_BIND_SERVICE and, for ICMP, CAP_NET_RAW, with no CAP_NET_ADMIN.
Public listener checks exclude only the current service's own PID.

TLS listeners use a private, persistent certificate per instance. Its SHA-256
fingerprint is shown in details and can be pinned on the dialing side. The PSK
authenticates the encrypted inner protocol even when no TLS pin is configured.
Certificate files survive reapply and rollback and are removed when deletion
commits. Actual service state and authenticated engine liveness are reported
separately; backend service access should also be checked with a real client.

## Validation

The regression suite covers all supported carrier/direction combinations,
IPv4/IPv6, concurrent random TCP transfers, UDP replies through 60,000 bytes
(ICMP uses 8192 at its default MTU), TLS certificate pins, restrictive validation,
credentials, service capabilities, transaction rollback, leases and UI flows
at mobile/desktop widths. Raw ICMP requires CAP_NET_RAW and is also exercised
on the privileged build runner. Local performance is not an Iran–foreign
benchmark or proof of superiority over another engine.

No database migration is introduced by this integration.
